Agentic code review · from Bonham Technologies

The unvarnished truth about internally built software

Companies are full of tools that nobody reviewed: the expense bot a manager built with an AI assistant, the spreadsheet macro that became a web app, the script that quietly runs payroll. Unvarnish reads them the way a careful engineer would, finds what a rushed reviewer misses, and says so plainly, with a file and line for every claim.

Who it's for

For the tools that grew up without an engineering team

Consultants vetting a client's tools

Run it unattended across every internal tool at a client. Each tool gets an architecture document, a findings document and a requirements document; across tools you get a comparison and a consolidation proposal to start your own architecture work from.

Teams inheriting AI-built tools

Before you rely on a tool someone generated, find the embedded secrets, the hardcoded servers, the 300-line functions, the missing tests and the single person who understands it.

Traditional codebases too

It works on code in any language: a repository with its full git history, or a pile of files copied off a shared drive.

What it finds

Deterministic scanners first, no model needed

Thirteen scanners run before any model sees the code. Their findings are reproducible and carry their evidence. Without a model configured, Unvarnish still writes the scanner-based findings document.

How it works

A pipeline of narrow roles, each checking the last

Each tool goes through nine phases. Every phase writes a JSON artifact with a hash of its inputs, so a rerun skips finished work and resumes after a stop. Every number, table and diagram in the documents comes from those artifacts; the model writes only the prose.

  1. Inventory, history, scan A census of every file and language, the git history (authors, bulk commits, AI tooling indicators) and the deterministic scanners.
  2. Split The code is cut into units along function and statement boundaries with tree-sitter, sized for the model's context.
  3. Extractor A model reads each unit and returns structured output: its purpose, the data it touches, the systems it calls, and findings with the lines that prove them.
  4. Summarisers Units roll up into modules, and modules into the tool: what it is for, who uses it, how it is deployed and how it was built.
  5. Verifier Each high or critical model finding goes to a verifier that sees only the claim and the cited lines. What it can't confirm is downgraded or rejected, what it can't check is marked unverified, and rejections are listed.
  6. Writer Architecture, findings and requirements documents, with diagrams, exportable to Word, HTML and PDF in your own branding. Findings also export to SARIF for GitHub code scanning and to CSV for a Jira import, and each tool's inventory to a CycloneDX SBOM, written offline (licences are listed only when the scan ran online).

Compare

unvarnish compare groups every tool's capabilities into one matrix, maps their shared data and integrations, compares their risk, and proposes a consolidation, listing every place it conflicts with the constraints you give it. It also writes a leadership brief: portfolio totals, one line per tool, the ten most severe findings and an action plan, every number counted from the results.

Ask

unvarnish ask "Which tool talks to Stripe, and from where?" answers from the analysis with cited sources. An answer that cites nothing is printed with an "unverified" warning.

Re-audit

unvarnish run --baseline ../acme-2026-04 compares a follow-up review with the last one. Each findings document opens with what was resolved, what is new and what changed since then, without another model call.

Run it

On your machine, with your models

Unvarnish is a command-line tool you run yourself; there is no hosted service. The code under review stays on the machine that runs it, and goes only to the model backend you configure.

Online

Use Anthropic's models with your own API key, read from an environment variable or the keychain and never written to disk. Set a token budget; run --dry-run estimates spend first.

On-prem

Point it at any OpenAI-compatible model server: vLLM, Ollama, LM Studio or a gateway. Per-phase models, timeouts and context sizes are configurable for slow CPU-only servers.

Air-gapped

A site kit carries the Docker image with gitleaks, osv-scanner, pandoc, Graphviz and dated offline advisory databases, plus checksums and a runbook, to a network with no internet access.

$ unvarnish init acme-2026-10 --client "Acme Corp" --consultant "Your Firm"
$ cd acme-2026-10
$ unvarnish add expense-bot --repo https://github.com/acme/expense-bot.git
$ unvarnish add receipt-ocr --files ~/Downloads/receipt-ocr
$ unvarnish run
$ unvarnish compare
$ unvarnish export --format docx

Requires Python 3.13+ and git; exports also need pandoc, Graphviz and weasyprint, or use the Docker image, which bundles them.
